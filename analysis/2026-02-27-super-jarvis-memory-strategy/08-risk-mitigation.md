# 风险清单与缓解策略

> **版本**: V1.0  
> **日期**: 2026-03-02  
> **目标**: 识别关键风险并提供可执行的缓解方案

---

## 1. 技术风险

### R-T1：记忆污染与错误固化

**风险描述**：

- 低质量记忆（模糊、重复、无意义）直接写入系统
- 错误记忆一旦固化，难以纠正且会持续影响决策
- 记忆冲突未被检测，导致矛盾信息共存

**影响等级**：🔴 Critical  
**发生概率**：高（当前 Admission Control 未充分利用）

**缓解策略**：

**短期（P0）**：

1. **强化 Admission Control**
   - 启用 `admission_enabled=true`
   - 实现记忆质量评分（Confidence Scoring）
   - 设置准入阈值：低于 0.5 的记忆不写入
2. **实现冲突检测**
   - 写入前检测与历史记忆的冲突
   - 高置信度冲突（>0.8）询问用户确认
   - 低置信度冲突（<0.5）自动合并或替换

3. **提供记忆编辑能力**
   - 用户可查看、编辑、删除记忆
   - 记录所有编辑操作的审计日志

**中期（P1）**：4. **记忆质量监控**

- 实时监控低质量记忆占比
- 告警阈值：低质量记忆 > 15% 触发告警

5. **自动清理机制**
   - 定期清理低置信度且长期未使用的记忆
   - 用户确认后执行清理

**验收指标**：

- 低质量记忆占比 <= 10%
- 用户纠错率 >= 5%（说明用户在使用纠错功能）
- 记忆冲突检测准确率 >= 80%

---

### R-T2：跨会话/跨渠道上下文丢失

**风险描述**：

- 用户在不同渠道（Telegram → Discord）切换时丢失上下文
- 长期项目的进展无法跨会话追踪
- 用户体验"助手健忘"，信任度下降

**影响等级**：🔴 Critical  
**发生概率**：高（当前缺乏项目上下文层）

**缓解策略**：

**短期（P0）**：

1. **实现项目上下文层**
   - 在 Graphiti 中建模项目实体（Project Entity）
   - 实现项目创建/更新/查询 API
   - 实现自动项目识别（基于对话内容）

2. **跨会话上下文注入**
   - 检索时自动关联到相关项目
   - 将项目上下文注入到对话中

**中期（P1）**：3. **跨渠道同步机制**

- 实现跨渠道的项目关联
- 用户在任何渠道都能访问项目上下文

4. **用户显式项目管理**
   - 提供 CLI/Web UI 管理项目
   - 用户可手动创建、归档、删除项目

**验收指标**：

- 项目上下文命中率 >= 70%
- 跨会话上下文保持率 >= 80%
- 用户满意度（长期任务）NPS +20 分

---

### R-T3：性能与延迟劣化

**风险描述**：

- W4 三路融合检索（Local + Mem0 + Graphiti）引入额外延迟
- p95 延迟可能超过 15% 的目标增幅
- 用户体验"助手变慢"

**影响等级**：🟡 High  
**发生概率**：中（W4 正在推进，需密切监控）

**缓解策略**：

**短期（W4）**：

1. **并行检索优化**
   - 确保三路检索真正并行（不串行等待）
   - 设置合理的超时时间（Local: 500ms, Mem0: 1s, Graphiti: 1.5s）
   - 任一路径超时不阻塞其他路径

2. **智能路由**
   - 精确 ID 查询直接走 Local（不调用远程）
   - 简单偏好查询优先走 Mem0（不调用 Graphiti）
   - 只有复杂查询才走三路融合

**中期（P1）**：3. **Smart Caching**

- 高频查询结果缓存（TTL: 5 分钟）
- 用户画像缓存（TTL: 1 小时）
- 项目上下文缓存（TTL: 30 分钟）

4. **Adaptive Routing**
   - 根据历史性能动态调整路由策略
   - 如果 Graphiti 持续慢，降低其权重

**验收指标**：

- p95 延迟增幅 <= 15%（相对 W3 baseline）
- 缓存命中率 >= 40%
- 用户感知延迟满意度 >= 8/10

---

### R-T4：Mem0/Graphiti 服务故障

**风险描述**：

- Mem0 或 Graphiti 服务不可用
- 网络抖动导致请求超时
- 系统整体不可用

**影响等级**：🟡 High  
**发生概率**：中（依赖外部服务）

**缓解策略**：

**短期（P0）**：

1. **Fallback 机制**
   - 远程服务故障时自动回退到 Local Memory
   - 保证基础功能可用（即使功能受限）

2. **健康检查**
   - 每分钟检查 Mem0/Graphiti 健康状态
   - 连续 3 次失败触发降级

**中期（P1）**：3. **多后端支持**

- 支持 Zep Cloud 作为 Graphiti 的备选
- A/B 测试验证可靠性

4. **断路器模式**
   - 连续失败后暂停调用（避免雪崩）
   - 定期重试恢复

**验收指标**：

- 系统可用性 >= 99.5%
- Fallback 成功率 >= 95%
- 故障恢复时间 <= 5 分钟

## 2. 产品风险

### R-P1：用户隐私与安全

**风险描述**：

- 敏感信息（密码、API Key）被记忆系统存储
- 跨渠道泄露（私聊内容在公开频道引用）
- 缺乏 GDPR/CCPA 合规的"被遗忘权"

**影响等级**：🔴 Critical  
**发生概率**：中（当前有基础过滤，但不完善）

**缓解策略**：

**短期（P0）**：

1. **增强敏感信息过滤**
   - 扩展检测规则（密码、API Key、邮箱、手机号、信用卡）
   - 检测到敏感信息时阻止写入或脱敏处理

2. **记忆访问权限控制**
   - 为每条记忆添加可见性标签（private/team/public）
   - 默认为 private，用户显式授权才共享

**中期（P1）**：3. **实现"被遗忘权"**

- 提供"删除所有记忆" API
- 级联删除所有相关记忆（Mem0 + Graphiti + Local）
- 记录删除操作的审计日志

4. **端到端加密（探索）**
   - 研究记忆数据的加密存储方案
   - 评估性能与可用性影响

**验收指标**：

- 敏感信息检测准确率 >= 95%
- 敏感信息泄露事件 = 0
- GDPR 合规审计通过

---

### R-P2：用户信任度下降

**风险描述**：

- 记忆错误频繁，用户不信任助手
- 记忆不可控，用户感到"被监视"
- 用户流失率上升

**影响等级**：🔴 Critical  
**发生概率**：中（取决于 P0 能力落地效果）

**缓解策略**：

**短期（P0）**：

1. **透明性优先**
   - 用户可随时查看助手记住了什么
   - 提供记忆来源追溯（哪次对话形成的）

2. **可控性优先**
   - 用户可编辑、删除任何记忆
   - 用户可冻结某条记忆（暂时禁用）

**中期（P1）**：3. **主动沟通**

- 定期提醒用户查看记忆（每月一次）
- 发现低质量记忆时主动询问用户

4. **用户教育**
   - 提供记忆管理教程
   - 展示记忆功能的价值（案例分享）

**验收指标**：

- 用户满意度 NPS >= 50
- 用户流失率 <= 5%
- 记忆功能使用率 >= 60%

## 3. 成本风险

### R-C1：API 调用成本超预算

**风险描述**：

- Mem0/Graphiti API 调用成本线性增长
- 三路融合检索导致成本翻倍
- 月度预算超支

**影响等级**：🟡 High  
**发生概率**：高（W4 三路融合后成本必然上升）

**缓解策略**：

**短期（W4）**：

1. **成本监控**
   - 实时监控 API 调用次数与成本
   - 按用户/项目归因成本
   - 告警阈值：单日成本 > 预算 120% 触发告警

2. **智能路由**
   - 精确 ID 查询不调用远程（节省成本）
   - 简单查询只调用 Mem0（不调用 Graphiti）

**中期（P1）**：3. **Smart Caching**

- 高频查询结果缓存（减少 API 调用）
- 缓存命中率目标 >= 40%

4. **成本优化策略**
   - 批量写入（减少写入次数）
   - 压缩记忆内容（减少存储成本）

**长期（P2）**：5. **混合架构**

- 核心用户用托管方案（Zep Cloud）
- 长尾用户用自建方案
- 根据 ROI 动态调整

**验收指标**：

- 月度成本 <= 预算
- 单用户成本 <= $0.50/月
- 缓存命中率 >= 40%

## 4. 执行风险

### R-E1：P0 能力延期

**风险描述**：

- P0 能力（记忆治理 API、项目上下文层）未能在 30 天内完成
- 影响后续 P1/P2 能力的推进
- 用户期望落空

**影响等级**：🟡 High  
**发生概率**：中（取决于团队资源与优先级）

**缓解策略**：

**短期**：

1. **并行实施**
   - Week 1-2 并行推进多个任务
   - 压缩工期（20 天 → 15 天）

2. **优先级调整**
   - 优先保证记忆治理 API（最核心）
   - 项目上下文层可延后到 P1

3. **资源保障**
   - 确保 2 名后端工程师全职投入
   - 减少其他非关键任务的干扰

**应急预案**：

- 如果 Day 20 仍未完成，立即启动应急评审
- 评估是否需要延期或缩减范围
- 与用户沟通调整预期

**验收指标**：

- P0 能力在 Day 30 前上线
- 无 P0 级阻断 bug
- 用户试点反馈 NPS >= 8/10

---

### R-E2：Zep Cloud 成本超预算

**风险描述**：

- Zep Cloud 试点期间成本超出预期
- ROI 不如自建方案
- 需要提前终止试点

**影响等级**：🟢 Medium  
**发生概率**：中（取决于 Zep 定价与使用量）

**缓解策略**：

**短期（P1）**：

1. **严格控制流量**
   - 试点期间只分配 10% 用户
   - 设置成本上限（如 $200/月）

2. **实时成本监控**
   - 每日统计 Zep API 调用成本
   - 接近上限时立即告警

3. **提前终止机制**
   - 如果成本超预算 150%，立即终止试点
   - 回退到自建 Graphiti

**应急预案**：

- 准备回退脚本（一键切换回自建方案）
- 保留自建 Graphiti 的完整能力

**验收指标**：

- Zep 试点成本 <= $200/月
- ROI 分析报告完成
- 决策：继续 vs 终止

## 6. 风险监控与响应

### 6.1 每周风险评审

**时间**：每周五下午  
**参与者**：项目负责人 + 工程师 + 产品经理

**议程**：

1. 回顾上周风险状态
2. 识别新风险
3. 评估缓解策略效果
4. 调整优先级与资源分配

### 6.2 风险告警机制

**自动告警**：

- 低质量记忆占比 > 15%
- p95 延迟增幅 > 20%
- 单日成本 > 预算 120%
- 系统可用性 < 99%

**人工告警**：

- 用户投诉记忆错误（>= 3 次/周）
- 用户流失率上升 > 5%
- P0 能力延期风险

### 6.3 应急响应流程

1. **识别风险**：通过监控或人工发现
2. **评估影响**：判断影响等级与紧急程度
3. **启动应急**：根据预案执行缓解措施
4. **跟踪恢复**：持续监控直到风险解除
5. **复盘总结**：分析根因，优化预案

---

## 7. 总结

**关键风险**：记忆污染、上下文丢失、隐私安全  
**核心策略**：透明性、可控性、可靠性  
**监控机制**：实时告警 + 每周评审  
**应急预案**：Fallback + 回滚 + 提前终止
