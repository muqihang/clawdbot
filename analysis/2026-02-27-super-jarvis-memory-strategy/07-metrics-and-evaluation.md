## 2. 质量指标详解

### 2.1 记忆命中率（Memory Hit Rate）

**定义**：用户查询时，系统返回的记忆中有多少是相关且有用的。

**计算公式**：

```
Hit Rate = (相关记忆数 / 总返回记忆数) × 100%
```

**采样方法**：

- 每周随机抽样 100 次用户查询
- 人工标注每条返回记忆的相关性（相关/不相关）
- 计算平均命中率

**目标值**：

- P0 阶段：>= 70%
- P1 阶段：>= 80%
- P2 阶段：>= 85%

**监控方式**：

- 实时监控：每小时计算一次
- 告警阈值：连续 3 小时 < 60% 触发告警

---

### 2.2 误召回率（False Positive Rate）

**定义**：系统返回的记忆中，有多少是不相关或错误的。

**计算公式**：

```
FPR = (不相关记忆数 / 总返回记忆数) × 100%
```

**采样方法**：

- 与记忆命中率使用相同的采样数据
- 标注不相关记忆（包括：完全无关、过时、错误）

**目标值**：

- P0 阶段：<= 20%
- P1 阶段：<= 15%
- P2 阶段：<= 10%

**监控方式**：

- 每日汇总报告
- 告警阈值：单日 > 30% 触发告警

---

### 2.3 记忆可信度分布（Confidence Distribution）

**定义**：系统中不同可信度等级的记忆分布情况。

**分级标准**：

- 高可信度（High）：>= 0.8
- 中可信度（Medium）：0.5 - 0.8
- 低可信度（Low）：< 0.5

**目标分布**：

- 高可信度：>= 60%
- 中可信度：20% - 30%
- 低可信度：<= 10%

**监控方式**：

- 每日统计分布
- 趋势分析：低可信度记忆占比上升 > 5% 触发告警

---

### 2.4 冲突检测准确率（Conflict Detection Accuracy）

**定义**：系统检测到的记忆冲突中，有多少是真实冲突。

**计算公式**：

```
Accuracy = (真实冲突数 / 检测到的冲突数) × 100%
```

**采样方法**：

- 每周收集所有检测到的冲突
- 人工验证每个冲突的真实性
- 计算准确率

**目标值**：

- P0 阶段：>= 70%
- P1 阶段：>= 80%
- P2 阶段：>= 85%

**监控方式**：

- 每周汇总报告
- 误报率（False Positive）：<= 15%

## 3. 用户体验指标详解

### 3.1 用户纠错率（User Correction Rate）

**定义**：用户主动编辑或删除记忆的频率。

**计算公式**：

```
Correction Rate = (用户编辑/删除操作数 / 总记忆数) × 100%
```

**目标值**：

- P0 阶段：5% - 10%（说明用户在使用纠错功能）
- P1 阶段：3% - 8%（记忆质量提升，纠错需求下降）
- P2 阶段：<= 5%（记忆质量稳定）

**监控方式**：

- 每日统计纠错操作数
- 分析纠错原因（错误记忆、过时记忆、隐私删除）

---

### 3.2 记忆编辑频率（Memory Edit Frequency）

**定义**：用户平均每周编辑记忆的次数。

**计算公式**：

```
Edit Frequency = 总编辑次数 / 活跃用户数 / 周数
```

**目标值**：

- P0 阶段：>= 1 次/周（说明用户在使用编辑功能）
- P1 阶段：0.5 - 1 次/周（记忆质量提升）
- P2 阶段：<= 0.5 次/周（记忆质量稳定）

**监控方式**：

- 每周统计编辑频率
- 分析编辑类型（内容修正、可信度调整、标签添加）

---

### 3.3 用户满意度（NPS）

**定义**：用户对记忆系统的整体满意度。

**采样方法**：

- 每月向活跃用户发送 NPS 问卷
- 问题："您有多大可能向朋友推荐 OpenClaw 的记忆功能？"（0-10 分）

**计算公式**：

```
NPS = (推荐者比例 - 贬损者比例) × 100
推荐者：9-10 分
中立者：7-8 分
贬损者：0-6 分
```

**目标值**：

- P0 阶段：NPS >= 30
- P1 阶段：NPS >= 50
- P2 阶段：NPS >= 70

**监控方式**：

- 每月计算 NPS
- 收集用户反馈（开放式问题）

---

### 3.4 长期任务完成率（Long-term Task Completion）

**定义**：跨多次会话的任务中，有多少最终完成。

**计算公式**：

```
Completion Rate = (完成的任务数 / 创建的任务数) × 100%
```

**目标值**：

- P0 阶段：>= 40%（基础项目上下文）
- P1 阶段：>= 60%（主动提醒）
- P2 阶段：>= 70%（时机感知优化）

**监控方式**：

- 每月统计任务完成率
- 分析未完成任务的原因（用户放弃、系统未提醒、上下文丢失）

## 4. 性能指标详解

### 4.1 检索延迟（Retrieval Latency）

**定义**：从用户发起查询到返回结果的时间。

**测量点**：

- p50（中位数）
- p95（95 分位）
- p99（99 分位）

**目标值**：

- P0 阶段：p95 <= 2 秒
- P1 阶段：p95 <= 1.5 秒
- P2 阶段：p95 <= 1 秒

**监控方式**：

- 实时监控（每分钟计算一次）
- 告警阈值：p95 > 3 秒持续 5 分钟触发告警

---

### 4.2 写入延迟（Write Latency）

**定义**：从记忆提取到写入完成的时间。

**测量点**：

- P3 Outbox 入队延迟
- Mem0/Graphiti 写入延迟
- 端到端延迟（提取 → 写入完成）

**目标值**：

- P0 阶段：端到端 p95 <= 5 秒
- P1 阶段：端到端 p95 <= 3 秒
- P2 阶段：端到端 p95 <= 2 秒

**监控方式**：

- 实时监控 P3 Outbox 队列长度
- 告警阈值：队列积压 > 100 条触发告警

---

### 4.3 系统可用性（Availability）

**定义**：记忆系统的可用时间占比。

**计算公式**：

```
Availability = (正常运行时间 / 总时间) × 100%
```

**目标值**：

- P0 阶段：>= 99%
- P1 阶段：>= 99.5%
- P2 阶段：>= 99.9%

**监控方式**：

- 健康检查（每分钟一次）
- 告警阈值：连续 3 次健康检查失败触发告警

---

## 5. 成本指标详解

### 5.1 API 调用成本（API Cost）

**定义**：Mem0/Graphiti API 调用的总成本。

**计算公式**：

```
Total Cost = Mem0 Cost + Graphiti Cost
Mem0 Cost = (搜索次数 × 搜索单价) + (写入次数 × 写入单价)
Graphiti Cost = (搜索次数 × 搜索单价) + (写入次数 × 写入单价)
```

**目标值**：

- P0 阶段：<= $500/月（假设 1000 活跃用户）
- P1 阶段：<= $0.50/用户/月（通过缓存优化）
- P2 阶段：<= $0.30/用户/月（通过智能路由优化）

**监控方式**：

- 每日统计 API 调用次数与成本
- 按用户/项目归因成本
- 告警阈值：单日成本 > 预算 120% 触发告警

## 6. 评估方法

### 6.1 离线评测（Offline Evaluation）

**目的**：在不影响用户的情况下评估新功能。

**方法**：

1. 构建评测数据集（至少 100 个样本）
2. 运行 baseline 与 variant
3. 对比指标（Top1、FUR、p95）
4. 证据落盘

**频率**：

- P0 阶段：每周一次
- P1 阶段：每两周一次
- P2 阶段：每月一次

---

### 6.2 在线 A/B 测试（Online A/B Testing）

**目的**：在真实用户场景中验证新功能。

**方法**：

1. 选择 10% 用户作为实验组
2. 运行至少 7 天
3. 收集指标数据
4. 统计显著性检验（p-value < 0.05）

**决策标准**：

- 实验组指标显著优于对照组 → 扩大流量
- 实验组指标无显著差异 → 继续优化
- 实验组指标显著劣于对照组 → 回滚

---

### 6.3 用户访谈（User Interviews）

**目的**：深入理解用户需求与痛点。

**方法**：

1. 每月选择 5-10 名活跃用户
2. 进行 30 分钟访谈
3. 记录用户反馈与建议
4. 提炼关键洞察

**关键问题**：

- 你最常使用记忆功能的场景是什么？
- 你遇到过记忆错误吗？如何处理的？
- 你希望记忆系统增加哪些功能？
