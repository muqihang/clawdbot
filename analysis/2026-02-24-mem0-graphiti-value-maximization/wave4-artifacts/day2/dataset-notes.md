## Dataset Schema (frozen)

JSON array. Each sample contains:

- `id`: stable sample id (g4v1-\*)
- `bucket`: `exact_id | decision_reason | temporal_relation | project_context`
- `query`: short natural query
- `aliases?`: optional alias queries (not scored for Top1; audit-only)
- `expected_ids`: non-empty list of gold remote ids
- `expected_structures?`: optional (`facts|episodes|nodes`) for audit

## Sample Size (hard gate)

Per bucket sample size:

- `exact_id`: 30
- `decision_reason`: 30
- `temporal_relation`: 34
- `project_context`: 30

Total samples: 124

If any bucket drops below 30 after verification, the dataset becomes **low_confidence** and Gate-4 must be treated as **NO-GO**.

## Dedupe Policy (frozen)

Aligned with `wave4-execution-task-packages.md` frozen rules:

1. **Within-bucket `expected_ids[0]` must be unique** (avoid over-weighting a single fact/entity).
2. **Within-bucket `query` must be unique** (aliases are allowed and do not count as query duplicates).

This dataset build enforces both (within each bucket).

## Source + Generation Method (traceable)

### temporal_relation bucket

- Imported from Wave3 Gate-3 final temporal dataset and re-labeled into Gate-4 schema:
  - Source: `analysis/2026-02-24-mem0-graphiti-value-maximization/wave3-artifacts/day10/w3-d-gate3-final/inputs/retrieval-temporal-dataset.v1.json`
- Rationale: preserve continuity of the temporal bucket across waves.

### exact_id / decision_reason / project_context buckets

- Generated by querying the **local Graphiti stack** `POST /search` and turning returned items into samples.
- Each bucket adds a minimal query prefix to ensure the query reliably classifies into the intended bucket:
  - `exact_id`: uses strings containing an `endpoint_path` precision key (for example file paths or HTTP paths like `/messages`).
    - Note: we keep the **full path text** (not only the regex-matched prefix) to keep per-sample queries unique. The router only needs a substring match to trigger the precision key bucket.
  - `decision_reason`: prefixes with `为什么 ...` to force decision_reason query bucket.
  - `project_context`: prefixes with `what is ...` to force entity_attribute-style queries mapped to project_context.
- Seed queries are embedded in the build script for auditability.

Rebuild command (should be deterministic given stable Graphiti content):

```bash
bun analysis/2026-02-24-mem0-graphiti-value-maximization/wave4-artifacts/day2/scripts/build-gate4-dataset.ts
```

## Ground Truth Verification (hard)

Verifier command (calls Graphiti `GET /entity-edge/{uuid}`):

```bash
bun analysis/2026-02-24-mem0-graphiti-value-maximization/wave4-artifacts/day2/scripts/verify-gate4-dataset-ground-truth.ts \
  analysis/2026-02-24-mem0-graphiti-value-maximization/wave4-artifacts/day2/inputs/retrieval-gate4-dataset.v1.json
```

Expected: exit code `0` and `fail_count=0`.

If failures occur:

- remove the failing samples from the dataset (do not “pad” with unverifiable samples),
- record the removal count + reasons here,
- re-run the verifier until clean.
